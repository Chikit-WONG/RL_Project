1. Project Overview

This project studies Game Playing with Q-Learning using the FrozenLake environment. FrozenLake is a discrete grid-world task in which an agent starts from an initial state and must reach the goal while avoiding holes. We chose this topic because it matches the course focus on reinforcement learning fundamentals while remaining small enough for clear implementation and analysis. In particular, FrozenLake allows us to study exploration versus exploitation, temporal-difference learning, value estimation, and policy improvement in an interpretable setting where the learned behavior can be visualized directly.

2. Main Objectives

The project has three main objectives.

1. Implement a complete tabular Q-Learning pipeline for FrozenLake, including environment interaction, epsilon-greedy action selection, Q-table updates, training loops, evaluation routines, and reproducible logging.
2. Compare deterministic and stochastic settings of the environment. In deterministic FrozenLake, the chosen action is executed exactly. In stochastic FrozenLake, the agent may slip to neighboring directions. This comparison allows us to examine how transition uncertainty affects convergence speed, variance across runs, and final success rate.
3. Study the effect of key hyperparameters, especially the learning rate, on convergence speed and final performance.

3. Proposed Methodology

We will use standard tabular Q-Learning with an epsilon-greedy exploration strategy. The implementation will be written in Python and designed to run in a lightweight CPU environment. We plan to use the standard FrozenLake-v1 environment when available, while keeping a fallback implementation path if package compatibility becomes an issue.

The experimental plan is organized into three parts:

- Experiment 1: Deterministic FrozenLake. This serves as the basic sanity check. We expect Q-Learning to learn a successful path reliably in this setting.
- Experiment 2: Stochastic FrozenLake. This setting is more realistic and challenging because the agent must learn a policy that is robust to randomness caused by slippage.
- Experiment 3: Hyperparameter analysis. We will compare several learning-rate values, such as 0.01, 0.10, and 0.50, to evaluate their impact on convergence speed, training stability, and final policy quality.

To improve reliability, we plan to repeat each condition with multiple random seeds rather than relying on a single run. We will record training reward, evaluation success rate, and summary statistics across seeds, and we will produce learning curves, success-rate curves, and policy visualizations for analysis.

4. Expected Deliverables

The final outcome of the project will include the following deliverables:

- a runnable Python implementation of tabular Q-Learning for FrozenLake;
- experiment outputs including logs, plots, and summary tables;
- a written report explaining the problem setup, algorithm, experimental design, and findings;
- an interpretation of how deterministic versus stochastic dynamics and different learning rates influence Q-Learning performance.

We expect the deterministic environment to be easier, while the stochastic environment will better expose the limitations of simple tabular Q-Learning under uncertainty. The learning-rate comparison should provide a concrete example of why hyperparameter selection matters in reinforcement learning.

5. Project Scope and Feasibility

The scope is appropriate for the course because it is technically meaningful without requiring large-scale computing resources or deep neural network models. The environment is small enough for repeated runs and careful analysis, yet complex enough to demonstrate the key challenges of reinforcement learning, especially sparse rewards and stochastic transitions. Overall, this is a focused and feasible Track A project that matches the course emphasis on reinforcement learning principles and methods.
